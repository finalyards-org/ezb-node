# 2. Demo with two boards (ESP-IDF)

## Requires

- Two ESP32-C6 devkits
- ESP-IDF toolchain

	See [Setting up ESP-IDF manually](1.%20Setting%20up%20ESP-IDF%20manually.md) and follow its instructions.

>🚨 WARNING! The ESP32-C6 multicolored LED can be strong. DO NOT STARE directly at it! The author placed a little sticker on the LED, to diffuse its glow.

## Aim 🏝️

To have the examples

- [`HA_color_dimmable_light`](https://github.com/espressif/esp-zigbee-sdk/tree/main/examples/home_automation_devices/color_dimmable_light)
- [`HA_color_dimmable_switch`](https://github.com/espressif/esp-zigbee-sdk/tree/main/examples/home_automation_devices/color_dimmer_switch)

..working together, ensuring the toolchain works.

### Overview

![](.images/zigbee-demo.png)

**`HA_color_dimmable_light`**

- ZC (Coordinator) role
	- creates the network where `switch` can join
- behaves like a smart light
- receives Zigbee commands; steers a LED

**`HA_color_dimmable_switch`**

- ZR (Router) role
- behaves like a light switch

## Steps

### Build the binaries

Build both the binaries, according to instructions in above mentioned doc.

- `color_dimmable_light`
- `color_dimmable_switch`

>You find these in the `examples/home_automation_devices` folder.

>```
>$ idf.py set-target esp32c6
>```
>
>```
$ idf.py build
[...]
[100%] Built target color_dimmable_light.elf
[...]
```
>
>```
$ file build/*.bin
build/color_dimmable_light.bin: ESP-IDF application image for ESP32-C6, project name: "color_dimmable_light", version 989c64e, compiled on Apr 30 2026 18:35:50, IDF version: v5.5.4, entry address: 0x408003FC
```


### Launch

#### 0. Reset the flash (both devices)

The Zigbee network is stored in ESP32's non-volatile memory. On your first time (and after problems, perhaps) do this:

```
$ espflash erase-flash
``` 

Do this for both the devices.

#### 1. Flash the `light` application

```
$ espflash flash --monitor build/color_dimmable_light.elf --partition-table partitions.csv
[...]
I (419) COLOR_DIMMABLE_LIGHT: Initialize Zigbee stack
I (419) COLOR_DIMMABLE_LIGHT: Deferred driver initialization successful
I (419) COLOR_DIMMABLE_LIGHT: Device started up in factory-reset mode
I (719) COLOR_DIMMABLE_LIGHT: Formed network successfully: PAN ID(0x0755, EXT: 0xfc012cfffef90438), Channel(13), Short Address(0x0000)
I (809) COLOR_DIMMABLE_LIGHT: Network(0x0755) is open for 180 seconds
I (809) COLOR_DIMMABLE_LIGHT: Network steering completed
```

The network is now open for 180 seconds, for the `switch` application (and device) to join.

#### 1b. Flash the `switch` application (Controller)

```
$ espflash flash --monitor build/color_dimmable_switch.elf --partition-table partitions.csv
[...]
I (1276) COLOR_DIMMER_SWITCH: Network(0x8081) is open for 180 seconds
I (1276) COLOR_DIMMER_SWITCH: Joined network successfully: PAN ID(0x8081, EXT: 0xfc012cfffef90438), Channel(13), Short Address(0xacd8)
I (1286) COLOR_DIMMER_SWITCH: Attempt to find HA color dimmable light device
I (1306) COLOR_DIMMER_SWITCH: Attempt to bind HA color dimmable light device (short address: 0x0000)
I (1316) COLOR_DIMMER_SWITCH: Bound HA color dimmable light device successfully
```

>Note that the "Extended PAN ID" matches with the `light`. So does the channel.


#### Troubleshooting

If you fail to connect, consider:

- have you erased the flash recently?
- reset the devices
- (+ write here, what helped..)

### Play time ⚗️

Press the button labeled `BOOT` on the `switch` device. The color on the other device should change.

Now, remove power from the `light` device for a moment. Reconnect. It should reconnect to the Zigbee network, and the `switch` button should still work.

>To bring back monitoring, `espflash monitor` and `Ctrl-R`.

Do the same for `switch`: OFF and ON.

Notice how the button keeps working - the Zigbee network is resilient.
